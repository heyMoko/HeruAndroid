# 일상 사용 구조

이번 구현은 녹음·서버·광고·결제 추가 전, 부모가 매일 사용할 수 있는 로컬 앱의 흐름을 정리한 것입니다.

## 사용자 흐름

- 오늘 화면에서 자녀별 활동을 확인합니다. 기본값은 식사 1번, 양치 2번, 정리 1번, 잠자리 1번이며 부모가 활동과 횟수를 바꿀 수 있습니다.
- 도움 요청은 표현 선택과 해루 통화로, 칭찬하기는 칭찬 선택으로 바로 진입합니다.
- 별 주기는 부모가 활동을 확인한 뒤 아이에게 별 받기 화면을 보여줍니다.
- 진행 중인 활동은 나중에 이어갈 수 있습니다. 화면을 벗어나면 재생을 중지하고 홈으로 돌아오며, 자동으로 다시 재생하지 않습니다.
- 별을 받는 순간 활동 완료 기록과 별을 함께 저장합니다. 이미 처리한 활동 ID는 다시 지급하지 않습니다.
- 별을 받은 뒤 별도 결과 설문은 없습니다. 중단하거나 변화가 없던 활동은 별 없이 기록할 수 있습니다.

## 저장과 복구

- Room 데이터베이스는 자녀, 보상 목표, 진행 중 활동, 완료·중단 기록, 별 지급 내역, 이관 여부를 저장합니다.
- 앱 시작 시 기존 SharedPreferences의 별·보상·최근 기록을 기본 자녀에 한 번만 이관합니다. 기존 설정 파일은 삭제하지 않습니다.
- 화면에 다음 단계를 보여주기 전에 저장합니다. 재생 중 단계는 부모가 다시 시작할 수 있는 단계로 정규화해 저장합니다.
- 데이터베이스 트랜잭션과 활동 ID를 사용해 완료 기록과 별 지급이 따로 남거나 중복 지급되는 것을 막습니다.
- 자녀 이름과 활동 설정을 수정해도 기존 기록과 별은 유지됩니다.
- 현재는 기기 내 보관입니다. 계정 동기화와 기기 이전 백업은 포함하지 않습니다.

## 보상

- 이번 목표의 별은 `전체 별 - 목표 시작 시점의 별`로 계산합니다.
- 현재 목표의 이름·사진·개수를 수정하면 진행을 유지합니다. 새 목표 만들기는 현재 전체 별을 시작점으로 삼아 0개부터 시작합니다.
- 목표 도달 안내는 확인 여부를 저장해 반복 노출을 막습니다. 선물을 실제로 제공했는지는 입력받지 않습니다.
- 별길의 칸 수는 목표 개수와 일치하며, 전체 누적 별을 따로 표시합니다.
- 사진은 선택 후 앱 전용 저장소에 크기와 방향을 조정해 복사합니다. 화면에서는 비동기로 읽습니다.

## 기록 해석

- 하루 완료 횟수는 실제 완료를 기록한 날짜를 기준으로 계산합니다.
- 하루 양치 두 번처럼 같은 상황을 여러 번 완료할 수 있습니다. 한 활동에서 같은 별을 여러 번 받는 것은 막습니다.
- '해루 경고 없이 기록한 활동'은 실제 경고 재생 여부에 따른 값입니다. 아이가 혼자 했는지나 앱의 훈육 효과를 추정하지 않습니다.
- 이전 버전의 '행동 시작' 기록을 새 버전의 '완료'로 간주하지 않습니다.

## 검증

- 순수 Kotlin 테스트: 목표 시작점·수정·상한, 중단 단계 복구, 경고 없는 칭찬, 완료 날짜별 횟수.
- Robolectric + 실제 Room 테스트: 기존 데이터 이관, 자녀 데이터 분리, 이름 변경 보존, 재실행 복구, 목표 변경, 달성 안내, 중복·동시 지급, 실패 시 트랜잭션 롤백.
- 앱 빌드와 Android Lint로 화면·리소스·API 연결을 확인합니다.

새 상황의 음성은 녹음 후 연결합니다. 보호자 공유, 알림, 클라우드 백업, 광고와 결제는 별도 제품 검증과 함께 진행할 다음 범위입니다.
